## 7. 恢复方法

优先从快照恢复到新目录，核验后再决定替换哪些文件。不要在未备份后续工作时覆盖当前项目，也不要使用未核实路径的递归删除命令。

以下示例仅作为恢复时的手动操作说明；它拒绝覆盖已存在的目标目录：

```powershell
$ErrorActionPreference = 'Stop'
$snapshotRoot = 'D:\new_blog\.backups\p0-20260930-1512'
$recoveryRoot = 'D:\new_blog\recovery-p0-20260930'
if (Test-Path -LiteralPath $recoveryRoot) { throw '恢复目录已存在，请选择新的目录。' }
New-Item -ItemType Directory -Path $recoveryRoot | Out-Null
Copy-Item -LiteralPath (Join-Path $snapshotRoot 'snapshot\project') -Destination $recoveryRoot -Recurse
$manifest = Get-Content -LiteralPath (Join-Path $snapshotRoot 'manifest.json') -Raw | ConvertFrom-Json
foreach ($entry in $manifest.files) {
    $restoredFile = Join-Path (Join-Path $recoveryRoot 'project') $entry.path
    $actual = (Get-FileHash -LiteralPath $restoredFile -Algorithm SHA256).Hash
    if ($actual -ne $entry.sha256) { throw "恢复校验失败：$($entry.path)" }
}
'恢复副本已与快照清单一致。'
```

恢复源码后，如需运行，在恢复目录执行 `npm.cmd ci` 重新安装依赖，并使用现有 Hugo 工具与 D 盘缓存。不要把旧 `.hugo_build.lock` 恢复回来；Git 远端信息也不会随本快照恢复。

按需单文件恢复时，从 `snapshot/project/` 选择对应文件，先保存当前文件的副本，再替换并与 `manifest.json` 核对。P0 完成后的宪章、计划进度和本记录不在执行前快照中，回退时应保留当前这几份记录，避免误把进度退回“尚未开始”。
