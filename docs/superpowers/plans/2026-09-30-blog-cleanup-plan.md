## 1. 本轮边界与方案选择

| 方案 | 结果 | 取舍 |
|---|---|---|
| A. 去个人化、关闭服务、保留展示能力（采用） | 得到可以继续魔改的干净博客 | 需要梳理组件依赖和关闭状态，但保留现有积累 |
| B. 只留文章、分类、归档、搜索 | 更小的最简博客 | 相册、动态、画板等日后需要重新接回，不符合已选方向 |
| C. 所有功能继续开启，仅改地址 | 外观变化较小 | 自有 API 尚未提供，容易残留占位地址或回退到陌生服务，不适合当前阶段 |

本轮做：删除作者数据、取消作者服务绑定、删除隐藏回退、补齐关闭与空数据状态、清理失去引用的个人素材、将必要展示依赖本地化。

本轮不做：重写 UI、迁移 React/Vue、实现后端、创建数据库、部署上线、购买域名、配置尚未提供的 API、删除 Git 历史或批量重命名主题内部标识。

“删除”指从当前源码、内容和发布产物移除。用户随后明确要求移除原仓库的本地 `.git`，以后使用自己的 GitHub 仓库，此要求取代原计划中保留原 Git 历史的安排。原提交号仅为盘点来源记录，不再作为本地回退点；在新 Git 仓库建立前，以文件备份和校验记录回退。不要把被删除的个人文件改放进另一个仍会随站点发布的目录。

“关闭”指默认不渲染对应服务入口、不加载客户端、不进行请求，保留可以复用的展示组件。单篇文章的 front matter 不得绕过全局关闭开关重新启用外部服务。

| 作者 GitHub 静态资源补齐 | `fetch-missing-static.mjs` 及 dev/build 调用 | 删除该作者绑定的脚本；缺资源在本地修复，不自动下载原素材 |

### 4.2 展示依赖本地化

“关闭非官方 API”与“删除所有开源组件”是两回事。保留展示能力需要处理以下组件；仅把脚本下载成本地文件仍不足以保证不联网。

| 组件 | 处理方式 | 验证要点 |
|---|---|---|
| Iconify | 固定当前组件版本到本地，按模板、配置及中性内容提取所需图标并本地注册；关闭运行时远程补图机制 | 不请求 `code.iconify.design`、`api.iconify.design` 或备用域名；缺失图标显示本地后备 |
| Fuse.js 7.0.0 | 固定版本，放入 `static/vendor/fuse/`，搜索页读取本地地址 | 断开外网仍能搜索本地文章 |
| Excalidraw embed 0.18.4 | 保留画板能力，将依赖入口、样式及实际引用的字体/分块资源纳入本地构建或 vendor 目录 | 不能只改入口 URL；画板加载、缩放时也无外部请求 |
| APlayer/Meting、Twikoo/Waline | 本轮关闭时完全不加载，保留组件适配代码 | 未启用不会从 jsDelivr/unpkg 请求，也不进行 DNS 预取 |
| ECharts、KaTeX、中文字体、本地特效 | 已有本地文件，继续使用 | 保留必要字体、声明和样式引用，避免为减体积破坏展示 |

资源获取仅用于准备固定版本的开发依赖；完成安装和资源准备后，默认 dev/build 不应抓取第三方业务数据。首次安装依赖或云端安装 Hugo 的官方分发请求不等于访客运行时请求，应在文档中分别说明。

最终默认站点的资源及数据请求只访问本站；允许的外部普通超链接（如主题来源、许可证说明）不算自动资源请求。此目标需要浏览器验证，不能只用 URL 文本搜索判定。

## 6. 验收矩阵与操作约定

| 验收对象 | 检查方式 | 通过标准 |
|---|---|---|
| 构建 | 干净产物目录执行原 `npm run build`；资源已安装后阻断外部业务网络再构建 | 两次均成功；不依赖作者资源、RSS、Bilibili 或音乐接口 |
| 开发启动 | `npm run dev` | 无隐式抓取，预览可访问，修改文章仍热更新 |
| 页面 | 首页、欢迎文章、排版示例、分类、标签、归档、关于、相册、动态、友链、留言、搜索、画板、追番空状态 | 无模板错误、断图、旧作者内容或无限加载 |
| 交互 | 搜索、主题切换、菜单、图片预览、画板缩放、PJAX 与浏览器后退 | 正常；不因重入页面重新开启已关闭服务 |
| 布局 | 至少 390px、1440px 两种视口 | 核心内容和空状态正常，隐藏的服务不留下空白浮层 |
| 身份清理 | 源文件检查加生成 HTML、RSS、sitemap、搜索数据检查 | 作者邮箱、账号、备案、推广域名和个人文案无非例外残留 |
| 素材清理 | 文件路径清单、原素材哈希与新产物比对 | 已删除素材不能通过旧静态路径继续访问 |
| 外部请求 | 干净浏览器配置、禁用缓存、记录 Network；等待延迟加载并触发搜索/画板/相册等交互 | 默认配置下，本站以外的资源与 API 请求为 0；不以请求失败代替未请求 |
| 开关语义 | 针对“全局 false + 单页 true”“none provider”“空端点”“旧缓存存在”做定向回归 | 不加载 SDK、不发请求、不展示失效服务入口 |
| 空数据 | 将栏目列表设空后构建与访问 | 正常空状态，无错误按钮或不可用控件 |

静态检查应区分三类 URL：自动资源/API 请求、仅点击后跳转的链接、文档/许可证中的来源记录。SVG 的 XML 命名空间也不是实际请求，不能用“出现 http 即失败”的规则。

示例检查命令（只读；命中结果逐条分类，不直接执行替换）：

```powershell
Set-Location D:\new_blog\HUGO_BLOG
git status --short
rg -n --max-columns 240 'yybb\.us|20030327\.xyz|334423445|2580064383|20260258|x@yybb\.us' hugo.toml content data themes/aiovtue scripts static -g '!*.min.js'
rg -n --max-columns 240 'kafuchino|i-meto|injahow|qjqq|hitokoto\.cn|busuanzi|s0\.wp\.com|dicebear|your-twikoo-url|your-waline-url' hugo.toml content data themes/aiovtue scripts
rg -n 'fetch-missing-static|fetch-links-rss|fetch-bangumi' package.json scripts/build.mjs
```

本地构建环境沿用已安装工具；运行前处理好本任务的 Hugo 开发服务，避免构建锁冲突：

```powershell
$env:PATH = 'D:\new_blog\.tools\hugo;' + $env:PATH
$env:HUGO_CACHEDIR = 'D:\new_blog\.cache\hugo'
Set-Location D:\new_blog\HUGO_BLOG
npm.cmd run build
```

源码检查允许保留本计划、来源文档、许可证及解释配置用法的记录；这些例外不应进入自动请求白名单。检查新发布产物时不允许出现原个人资料。对被保留的源码归属和页脚主题来源单独记录例外，不做全库 `AIOVTUE` 或“雪”字替换。
