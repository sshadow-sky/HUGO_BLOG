# ShadowSky 可视化后台开发计划

> 状态：2026-10-01 A0 本地适配、真实 GitHub App 安装/站长登录/私有仓库读取已验证。A1 本地文章与媒体配置已准备并通过隔离测试，远端同步及真实编辑保存仍待验收；A2–A5 未开始。
> 后续实施按项目宪章逐步说明与验收；使用 `superpowers:executing-plans` 时，先把已确认阶段展开为具体实施任务，不把本路线图视为全部执行授权。

**目标：** 基于 Pages CMS 建立适配 ShadowSky 的个人管理后台，逐步覆盖文章整理、资源管理、发布、访问统计与站点运行信息。

**推荐架构：** 自托管 Pages CMS，复用其 GitHub 内容编辑能力，在独立后台应用中增加本站概览与服务适配层。公开博客继续使用 Hugo，文章仍保存在现有私有 GitHub 仓库。

**技术方向：** Hugo / Markdown / TOML / YAML、Pages CMS 上游技术栈、PostgreSQL、GitHub App 与 Actions；具体上游版本在第一阶段核实并固定。

## 已确认与推荐项

- **用户已确认：** 首先只供自己使用，保留将来扩展多人权限的空间。
- **用户已要求：** 先编写计划书，对开发需求与开发思路分类；文章整理、流量监控属于目标范围。
- **推荐但尚未实施：** 自托管 Pages CMS，并进行小范围二次开发；后台源码与 Hugo 内容仓库分开维护。
- **延续现有约定：** 当前内容仓库为 `sshadow-sky/HUGO_BLOG`，开发分支为 `best`；相册保留，桌宠调整搁置，统计继续使用第三方，正式域名统计验收仍在[部署后清单](../../post-deployment-todo.md)。不迁移 Astro 项目。

本计划按“内容管理、发布流程、管理看板”三个子项目交付。先得到可用的文章管理入口，再接发布与运营信息，避免首版同时依赖所有外部服务。

## A0 可行性与适配验证

**方向与理由：** 先证明 Pages CMS 能正确编辑本站文件，并确认二次开发成本。此时只做隔离验证，防止后台保存时改变公式、短代码、资源地址或配置含义。

**涉及位置：** 当前仓库的 `archetypes/`、`content/`、`hugo.toml`、`data/links.yaml` 作为只读依据；试验配置及样本放在独立验证目录/分支，上游源码位置在开始本步时确定。

- [x] 固定 Pages CMS 上游仓库、版本或提交，记录许可证、运行环境和升级方式；检查与本计划引用文档是否一致。已锁定 2.1.8 / `6f4e860`。
- [x] 验证真实站长登录、私有仓库 best 读取和 GitHub App 仅安装到选定仓库；单用户拒绝策略已测试，真实第二账号拒绝保留未验证。
- [x] 明确本地与远端基线。开始验证时本地 `0b5dfa7` 比远端 `5562e0f` 多 28 个提交；未推送，同步属于后续接入前步骤。
- [x] 用一次性样本验证 TOML/YAML front matter、中文文件名、正文源码、图片、公式、短代码、画廊布局和画板附件的本地保存往返。范围为源码函数及隔离 Hugo 构建，不含完整 CMS 浏览器/远程保存。
- [x] 验证 `settings.content.merge: true` 对未配置字段的保护，另外检查注释、类型、日期及正文是否变化。发现空值清理、注释丢失和日期控件精度风险，详见报告。
- [x] 核实原生页面定制的扩展位置，并调查统计服务查询方式。找到官方查询页面，未验证到可用的只读 JSON API；暂不开启看板轮询。

**本地验证后的方案调整：** A1 正文采用 Markdown 源码编辑，日期先保留完整 ISO 文本，增加 `math` 开关；整份站点配置只读。混合格式、空值清理和友链 YAML 顺序风险需适配后才开放相关编辑。下一小步为 A0.2：独立后台最小运行环境与 GitHub App/单站长准入联调。

**验收：** 输出能力矩阵、样本保存前后差异、Hugo 渲染对照、推荐版本与必须补充的适配工作。若可视编辑损坏复杂正文，先交付元数据表单加源码编辑，不以丢失内容换取可视化。

**回退：** 丢弃隔离样本和试验配置；现有博客内容与预览保持原样。

## A1 文章与媒体管理首版

**方向与理由：** 先让你可以登录、找文章、写草稿、上传图片并保存。这是日常使用频率最高、最容易独立验收的部分。

**拟新增/调整：** Hugo 仓库根目录 `.pages.yml`、新资源目录 `static/uploads/`、必要的文章 archetype；后台应用中的账号准入和本站导航。具体后台源码路径依据 A0 选定版本确定。

- [x] 仅允许 `sshadow-sky` 对应的已验证 GitHub 账号登录；服务端检查身份、仓库和分支，禁用首版不需要的注册/邀请入口。
- [x] 建立普通文章集合：标题、日期、草稿、简介、封面路径、分类、标签、正文；排除栏目 `_index.md`。A1.2 已同步并读取远端配置。
- [ ] 提供标题搜索、日期排序、分类/标签及草稿筛选；原生视图不足的筛选作为小范围扩展。
- [x] 配置图片上传目录与公开路径、服务端解码/体积校验；源码用 Markdown 图片语法和替代文字，新增文章默认草稿。A1.2 真实上传和草稿闭环已通过。
- [x] 显示当前编辑分支与保存结果；保存成功指 GitHub 提交成功，不显示为“已上线”。
- [ ] 并发冲突、网络失败/恢复、保存期间继续输入已通过真实浏览器验收；上传失败的完整交互和会话自然过期仍待验收。尚未引入持久化浏览器草稿恢复。

**验收：** 完成“登录 → 新建含文字/图片/公式的草稿 → 保存 → 重新打开 → 修改 → 再次读取”闭环；账号越权和覆盖较新版本被拒绝，内容与 A0 样本一致。

**回退：** 撤销 CMS 配置和本阶段内容提交；不删除共用媒体、不改生产部署。后台停止后静态博客仍能正常工作。

## A2 本站内容类型与站点资料

**方向与理由：** 在普通文章稳定后，补齐本站特有的画廊、画板、动态和友链；避免把不同数据格式硬塞进同一种文章编辑器。

**涉及位置：** `.pages.yml`、`content/posts/`、`content/excalidraw/`、`content/moments/`、`content/about.md`、`data/links.yaml`；必要时调整 `scripts/fetch-links-rss.mjs` 的 YAML 解析。现有相册先只读展示。

- [ ] 为画廊文章提供独立新建入口，写入 `layout: gallery-post`，保留图片顺序与说明。
- [ ] 为画板提供说明编辑及 `.excalidraw` 文件上传，校验附件属于同一页面 bundle；首版不内嵌绘图工具。
- [ ] 支持动态与关于页编辑，保持动态栏目索引中的 `cascade` 配置。
- [ ] 支持友链分组与 RSS 地址。先修复或验证 RSS 读取器对 YAML 字段顺序的依赖，再开放表单保存；默认只聚合当前脚本支持的第一组，不静默扩大订阅范围。
- [ ] 提供站点资料只读页；仅在验证配置写回安全后，逐项开放名称、简介、社交入口、公告等字段。
- [ ] 相册内容继续保留，编辑器只在用户要求且通过无损验证后开放。桌宠配置不纳入本阶段。

**验收：** 三类文章能正确进入对应 Hugo 模板；动态仍在动态页显示；友链保存后第一组 RSS 来源与编辑前预期一致；相册和未编辑配置没有变化。

## A3 预览与正式发布

**方向与理由：** 把“保存内容”与“发布网站”清楚分开，提供能核对文章实际显示效果的 Hugo 预览。

**拟新增：** `.github/workflows/cms-preview.yml`、`.github/workflows/cms-publish.yml` 及 `.pages.yml` 中的 Actions 配置；当前仓库没有 `.github` 工作流，这些是拟建文件。部署目标在本阶段开始时选定。

- [ ] 从经确认的基线建立内容编辑分支，建议名 `cms-content`；保留 `best` 的现有开发用途，具体分支规则见技术设计。
- [ ] 为保存后的确定提交生成隔离预览，预览不计入正式统计，草稿预览受访问控制。
- [ ] 发布前核对完整变更、构建结果、提交 SHA 与生产目标；生产构建不带 `-D`。
- [ ] 将操作按钮接到工作流，服务端/工作流校验允许的操作、分支和提交；不执行表单提供的任意命令。
- [ ] 显示排队、构建、部署、失败状态及对应提交；测试发布期间有新提交时不会把未预览内容混入本次发布。
- [ ] 保存最近成功的发布产物与版本，测试失败时保留旧站点及回退到上一版本。

**验收：** 保存草稿不会直接上线；预览和发布版本能对应；构建失败不替换线上页面；一次故障演练可以恢复上一成功版本。

**依赖：** 正式发布需明确托管平台、部署凭据和域名配置。未具备时可以交付预览与构建状态，发布按钮显示“尚未配置”，不虚报上线成功。

## A4 本站管理看板

**方向与理由：** 在内容与发布可靠后，汇总真正有来源的信息，方便你判断网站是否正常运行。

**拟新增模块：** 后台站点概览、统计适配器、发布状态适配器、评论入口和服务状态组件；详细数据责任见技术设计。

- [ ] 展示当前分支文章数、草稿数、最近修改、最近构建与最近发布版本，标出统计范围和更新时间。
- [ ] 接入经核实的第三方只读统计数据；先提供确实可获取的 PV/UV 指标，再决定是否开放趋势、来源与热门页面。
- [ ] 无只读统计接口时显示原因与可用的官方管理入口；保持第三方服务选择，不自动改建统计后端。
- [ ] 提供 Twikoo 管理入口及不产生访客记录的连接状态检查；内嵌审核、删除评论另作扩展。
- [ ] 展示 RSS/追番最近更新、成功/失败/未配置/隐私受限等状态，不把抓取失败显示为零条数据。
- [ ] 全部卡片区分真实零值、未接入、加载失败和过期缓存，故障可重试且不阻断文章编辑。

**验收：** 与来源逐项核对；连续刷新后台不会制造前台访问统计；不出现虚构趋势图；第三方超时或撤销凭据后，文章管理仍正常。

## A5 运维操作与上线交接

**方向与理由：** 最后把已有手动工具接成受控操作，再完成后台部署、备份与使用说明。

- [ ] 为 `npm run update:links` / `npm run update:bangumi` 提供明确的手动更新按钮、超时和结果记录；不恢复打开网页或普通构建时的自动抓取。
- [ ] 明确生成缓存的持久化与发布路径；两份 JSON 当前被 Git 忽略，不能假设另一台构建机器能读到本地结果。
- [ ] 进行管理页窄屏、键盘、深浅色和减少动画偏好验收；采用 ShadowSky 配色，但输入区域不播放干扰编辑的特效。
- [ ] 配置后台 HTTPS、GitHub 回调/Webhook、仅内部可达的数据库与敏感配置；后台域名建议 `admin.shadowssky.com`，尚未创建。
- [ ] 备份并演练恢复 CMS 数据库、必要加密密钥、Twikoo 数据和发布产物；Git 仓库备份不能替代这些数据。
- [ ] 编写站长手册：写文章、上传图片、预览、发布、失败恢复、评论管理、统计口径、升级方式。

**验收：** 从备份恢复后仍能登录、读写内容并查看正确版本；手动更新产物可进入指定预览/发布；正式域名统计按原部署后清单单独完成验收。
