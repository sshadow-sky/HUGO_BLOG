# A1 本站内容管理接入计划

> 用户已确认开始本站内容管理配置，并隐藏未开放入口、补充中文说明。使用 superpowers:subagent-driven-development 执行，现有独立后台与 Hugo 工作目录、best 分支沿用用户指定位置，不新建副本替换正在预览的工程。

**目标：** 准备适配本站的普通文章与图片管理配置，修复 A0 已发现的保存兼容风险，改善当前后台入口提示。

**架构：** Hugo 根目录 `.pages.yml` 定义内容与资源映射；独立 Pages CMS 后台负责编辑及保存校验。远端内容仍以 GitHub 为准，禁止用本地配置伪装远端接入成功。

**技术：** 固定版本 Pages CMS、Next.js、TOML/YAML front matter、Markdown 源码、Hugo。

## 本步设计与边界

- 普通文章集合映射 `content/posts/`，排除栏目索引；新文章采用 TOML、默认草稿，标题、ISO 日期、简介、封面、分类、标签、math 及源码正文采用中文字段。
- 图片媒体映射 `static/uploads/` → `/uploads/`，只开放位图类型。相册、动态、友链、Hugo 配置不纳入本步编辑。
- 保存保留既有 TOML/YAML 格式、未知字段、空数组、false 和正文特殊语法；不以富文本转换损失公式/短代码。格式不支持时拒绝写入。
- Actions、协作者及无法使用的分支管理入口隐藏；服务端限制继续保留。配置状态中文化，缺配置时不提供随意初始化模板的操作。
- 本步先完成本地可审查成果与隔离验证。项目宪章禁止夹带推送；同步远端 best 和真实远端保存需在具体同步范围准备好后由用户确认。该限制不影响本地实现与验收。
- 画廊/画板专用编辑入口仍属 A2，保持已有文件及素材；本步不新增永久演示文章。

## 验收与回退

本地配置须能被当前 CMS 解析；文章样本保存后正文、公式、短代码、HTML、日期和元信息含义保持，草稿不出现在生产构建。导航不暴露明确禁止使用的功能。只读核查远端，不提交测试文章。回退仅撤销本步新增配置及后台修改，不覆盖用户已有修改、凭据、数据库或相册。
