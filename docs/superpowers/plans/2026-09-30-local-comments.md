# 本地 Twikoo 评论服务实施记录

> 执行方式：按 executing-plans 在当前 best 分支逐项完成；用户已授权本地启动与后续迁移准备。

**目标：** 在本机运行评论后端，让 Hugo 开发预览可以读写评论，并将数据保存在可迁移目录。

**方案：** 使用官方 tkserver，与当前前端统一锁定 1.7.12；采用其 LokiJS 文件数据库，暂不引入 Docker 或 MongoDB。仅监听本机 127.0.0.1:8080。开发环境覆盖评论地址，生产配置不写本机地址。服务依赖与博客构建依赖分离。

**依据：** https://twikoo.js.org/backend.html#私有部署 。当前版本具体环境变量以已安装的 tkserver 源码为准。

- [x] 建立 services/twikoo 的独立包和锁文件，配置启动命令、持久数据目录及忽略规则。
- [x] 添加 config/development/params.toml，将开发预览连接到本机后端；生产不包含 localhost 评论端点。
- [x] 启动后端和预览，验证 API、实际评论提交和读取、重启持久性、页面与 PJAX。
- [x] 清除验证用评论，保留真实使用的空数据库；记录启动、停止、备份及迁移方式。
- [x] 更新宪章与 README，核验 Git 中不包含数据库、凭据或运行日志。

**验收方法：** 先确认 8080 未占用；安装后检查实际监听地址和版本。测试评论使用明确测试身份，验证后移除。停止服务再备份文件，避免复制尚未落盘数据；在服务器上使用同版本恢复后再单独规划升级。前端初始化和管理员入口用浏览器实测。仅本地运行，不推送远端或部署公网。

## 执行结果

- `npm run build` 成功，30 页面、665 静态文件；生产 HTML 未包含本地评论地址。重启开发服务后，评论 meta 指向 `http://127.0.0.1:8080`。
- 后端 `GET_FUNC_VERSION` 返回 1.7.12；系统监听检查为 `127.0.0.1:8080`。
- 配置本站名、本地站点地址、跨域来源及随机管理员密码。凭据仅保存在 `.local/twikoo-admin-password.txt`，未提交。管理员登录通过 API 验证；浏览器可见齿轮入口，未自动登录管理界面。
- API 提交/读取及浏览器真实表单发送通过；友链到留言页 PJAX 后评论组件正常。桌面和 390px 手机无横向溢出，成功测试期间无未捕获 JS 异常。初次测试选择器被 Twikoo 改名、脚本填值未触发表单校验，均通过修正测试方式解决，未更改主题代码。
- 两条测试评论写盘后停止服务，备份到 `D:\new_blog\.backups\local-comments-20260930`，重启后均可读取且管理员仍可登录。随后只删除这两条测试记录；接口与数据库分片检查均无测试标记，目前零评论。
- 证据位于 `D:\new_blog\.runtime\local-comments`：`browser-results.json`、`persistence-results.json`、桌面/手机截图与进程记录。
- `git diff --check` 通过，数据库、凭据和 node_modules 均被忽略。
