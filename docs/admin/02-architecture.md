# ShadowSky 后台技术设计

状态：2026-10-01 方案草案。[返回开发计划](../superpowers/plans/2026-10-01-admin-development-plan.md)。文中“原生能力”来自当前官方文档；“本站扩展”是拟开发内容，尚未验证或实现。

## 方案比较

| 方向 | 优点 | 成本与限制 | 建议 |
| --- | --- | --- | --- |
| 使用托管 Pages CMS，只添加 `.pages.yml` | 内容管理上线快，维护量小 | 任意管理看板不能只靠内容配置生成，通常要跳转外部服务 | 可作为内容管理验证方案 |
| 自托管 Pages CMS，增加本站管理模块 | 复用编辑能力，能统一管理入口和视觉 | 要维护应用、数据库及上游升级兼容性 | 推荐，符合专用后台目标 |
| 全部重写 CMS | 数据模型与界面自由 | 需要重做编辑器、媒体、认证、GitHub 写入等基础能力 | 当前不推荐 |

Pages CMS 直接编辑 GitHub 仓库文件，是内容编辑层，不替代 Hugo 或部署系统。因此，本站完整后台不能仅靠一份 `.pages.yml` 实现。[官方定位](https://pagescms.org/docs/)

## 原生与定制的边界

| 能力 | 实现来源 | 本站工作 |
| --- | --- | --- |
| 集合、单文件、字段、媒体选择 | 原生配置 | 映射本站目录、格式与字段 |
| 正文可视/源码编辑 | 原生编辑器 | 验证公式、短代码、混合格式往返；必要时使用源码模式 |
| GitHub 身份与仓库访问 | 原生认证基础 | 额外限制为本站和本人，验证所有服务端入口 |
| 触发 GitHub Actions 的按钮 | 原生 Actions 配置 | 编写预览/发布/更新工作流，校验操作参数与版本 |
| 本站概览、统计图表、服务汇总 | 本站扩展 | 增加页面与服务端数据适配器 |
| 评论审核 | 先使用 Twikoo 管理入口 | 如需内嵌，单独验证管理接口与认证，不假设已有插件 |

原生 Actions 可传递上下文和表单输入到 `workflow_dispatch` 的 `payload`，但工作流本身仍需创建。[Actions 文档](https://pagescms.org/docs/configuration/actions/)

当前自托管文档要求 PostgreSQL 与服务端密钥配置。文章保存在 Git，并不意味着 CMS 应用自身完全不需要数据库。[自托管指南](https://pagescms.org/docs/guides/installing/self-host/)

## 应用与数据归属

| 部分 | 数据/责任 | 不承担的责任 |
| --- | --- | --- |
| Hugo 内容仓库 `HUGO_BLOG` | Markdown、配置、主题、可版本管理资源、CMS 内容定义 | 不保存后台私钥与运行数据库 |
| 拟独立后台 `HUGO_BLOG_ADMIN` | Pages CMS 定制、服务端认证、概览与接口适配 | 不复制另一套文章主数据 |
| CMS PostgreSQL | 上游需要的身份/会话/缓存数据，以及经设计的操作记录 | 不取代 Hugo 内容文件 |
| GitHub/构建环境 | 内容版本、工作流、预览与发布产物 | 不把任意“最新分支”默认为本次发布版本 |
| 第三方统计、Twikoo | 各自统计与评论数据 | 不与文章 Git 历史混为一份备份 |

后台源码独立是推荐组织方式，本轮不创建新仓库。公开站点继续由 Hugo 构建；未来后台地址建议 `admin.shadowssky.com`，并非已部署地址。

## 身份与接口设计

首版以本人 GitHub 身份作为唯一入口，使用经过认证的稳定账号 ID 绑定，账号名用于展示；校验目标仓库为 `sshadow-sky/HUGO_BLOG`，分支属于允许集合。校验放在服务端，每次写入和触发工作流都检查，不仅隐藏界面按钮。

Pages CMS 支持 GitHub 用户令牌和安装令牌，并有仓库范围的协作者访问路径；本站首版不启用协作者入口。[认证文档](https://pagescms.org/docs/development/authentication/)

`ADMIN_EMAILS` 的官方含义是控制上游 admin panel 访问，不能直接当成整个应用的“仅本人可用”证明。A0 要检查登录、仓库、文件与自定义接口的完整准入。[环境变量说明](https://pagescms.org/docs/development/environment-variables/)

官方 GitHub App 指南列出的权限包含仓库管理、Actions 与内容写入；不能把其描述为只读授权。A0 应核对选定版本真正使用的权限，并把安装范围限制在本站仓库，精简权限后需重新验证功能。[GitHub App 指南](https://pagescms.org/docs/guides/installing/github-app/)

自定义接口统一做身份检查、参数校验和结果脱敏。密钥只在后台环境或部署平台保管；Webhook 验签，写操作防跨站请求与重复触发。对 RSS 等用户可配置远程地址限制协议与访问目标，禁止请求本机、内网和云元数据地址，并检查重定向目标。

## 保存、预览与发布

推荐在 A3 建立独立内容分支 `cms-content`，由已确认且同步到远端的 `best` 基线创建。工程开发继续在 `best`；内容分支与工程分支需要显式同步并处理冲突，不能悄悄覆盖彼此。

1. **保存：** CMS 写入编辑分支，返回确切提交 SHA。检查读取时文件版本；发现远端更新时提示冲突，保留本次输入。
2. **预览：** 对选定 SHA 做 Hugo 构建；预览可包含草稿，放入受访问控制的独立环境，关闭正式统计。
3. **准备发布：** 展示相对上次发布的完整差异，包括其他文章和工程文件；检查目标 SHA 已通过验证。
4. **发布：** 对该 SHA 进行生产构建，不带草稿参数，并部署该版本产物。分支在此期间前进不能改变本次目标。
5. **回退：** 重新部署保留的上一成功产物；需要恢复源内容时另做可审阅的 revert，不强推改写历史。

GitHub 保存是远程提交，不等于本站正式发布。A1/A2 验证期间不得连接自动生产部署；A3 才接正式发布流程。是否建立内容分支、分支保护与发布目标均在实施该步时明确，不在当前规划中改仓库设置。

文章的 `draft` 是内容属性；“正在构建”“已部署”“失败”来自任务记录，不能都压成一个文章布尔值。定时发布需要定时构建配合，单独修改文章日期不足以保证准时上线，首版不承诺此能力。

多文件文章及附件不假定 Pages CMS 原生支持一次原子提交。最小方案先完成全部保存再允许预览/发布；若验证发现不满足，需要新增 Git tree 提交适配，单独评估后实现。

## 流量监控的数据边界

延续用户选择：继续用 busuanzi.cc；本地预览不统计，正式计数上线后验收。现有 `themes/aiovtue/assets/js/statistics.js` 通过 POST 发送页面 URL 和 referrer，该路径参与访问上报，不能直接拿来让后台轮询，否则可能污染计数。

| 数据 | 当前证据 | 后台方案 |
| --- | --- | --- |
| 本站/今日 PV 与 UV | 前台已有字段适配，正式域名未验收 | 核实官方只读查询途径后接入，不直接复用上报调用 |
| 7/30 日趋势、来源、热门页面、实时在线 | 尚未证明当前服务提供所需查询能力 | 默认不显示图表；取得对应接口与口径后逐项开放 |
| 单篇阅读量 | 现有方向优先 Twikoo | 与整站统计分开，核实只读接口，避免读取时增加阅读量 |
| 服务器带宽与资源占用 | 尚未接监控源 | 后续独立连接服务器/云平台，不从 PV 推算 |

统计适配器拟统一返回：数据来源、指标、统计范围、时区、采集时间、有效期与状态。状态区分 `ok`、`not_configured`、`unsupported`、`error`、`stale`；只有来源明确返回零时才展示 0。

若服务没有适用的只读接口，后台先显示限制与可用的官方入口。需要其他统计产品时向用户提出单独选型，不擅自改为自建统计系统。日趋势不能通过事后读取累计数虚构，累计 PV/UV 也不能跨时段随意相加。

本轮打开统计服务文档超时，因此没有新增已验证的统计接口结论。现有约定与验收依据保留在[部署后清单](../post-deployment-todo.md)。

## 更新任务与评论

RSS 和追番复用现有脚本，默认仅手动触发。任务记录来源、开始/结束时间、结果摘要与脱敏错误；不记录令牌。Bilibili 返回隐私限制时展示“列表未公开”，不能解释为用户没有追番。

`data/links_rss.json`、`data/bangumi.json` 被 Git 忽略。推荐更新任务生成带来源提交与时间的版本化产物，预览/发布显式下载并校验后使用；普通构建不联网抓取。首次无缓存显示未生成，失败保留上一份同配置来源的成功产物并标记过期；来源配置改变时不得继续展示旧来源数据。具体存储/保留时间在部署平台选定后落实。

Twikoo 首版提供管理入口，继续使用其自身管理认证；后台不把管理员凭据嵌入前端或 URL。跨域管理页无法可靠嵌入时使用独立窗口，不绕过服务的安全限制。

## 故障、备份与升级

GitHub 请求失败时保留编辑状态；第三方故障只影响对应卡片。所有只读汇总有缓存和更新时间，重试需要限频；手动更新任务防止重复并发写入同一产物。

分别备份 Git 内容、CMS PostgreSQL 与加密密钥、Twikoo 数据、独立媒体和已发布产物。执行恢复演练，验证加密数据可解密、登录与读写可用；不把备份加入 Hugo 发布目录。

二次开发集中在本站模块，记录上游版本与定制差异，保留许可证。上游升级先运行内容往返、账号越权、冲突、工作流版本绑定测试，再更新生产实例，不自动追踪主分支部署。
