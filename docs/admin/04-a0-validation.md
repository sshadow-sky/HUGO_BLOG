# A0 本地兼容性验证报告

日期：2026-10-01。结论：**Pages CMS 可以继续作为后台基础，但不适合直接用默认富文本和通用配置表单接管本站。建议首版采用元信息表单与 Markdown 源码编辑，并增加针对本站的保存约束。**

本次完成上游源码核查、独立样本探针、Hugo 渲染对照与远端只读检查。GitHub App 登录、CMS 远程保存和账号拒绝测试尚未执行，因此 A0 为“本地验证完成、接入联调待完成”，不是后台已经可用。

## 验证结果

| 项目 | 实测/核查结果 | 接入决定 |
| --- | --- | --- |
| 普通文章、画廊、画板的源码保存 | 正确指定格式并合并未编辑字段后，三个样本正文保持一致 | 可继续适配 |
| Hugo 实际渲染 | 保存前后三个文章区域 HTML 完全一致；普通文章含 4 处公式、图片、表格、代码、短代码与折叠 HTML | 源码编辑作为首版正文入口 |
| 草稿 | 不带草稿开关的生产构建排除三个样本地址 | 保留 `draft`；保存与发布分开 |
| 未知字段与 false | 合并开启时未知字段及 false 保留；关闭合并会丢失未提交字段 | 开启合并，但不能仅依赖它保证无损 |
| 空字符串、空数组 | 上游 `sanitizeObject` 会删除它们，合并后也一样 | 编辑范围限定为文章；配置编辑前适配清理逻辑 |
| 注释与 TOML 类型 | front matter 注释丢失；TOML 时间经 JSON 转为字符串；样本日期语义仍能被 Hugo 识别 | 不能承诺字节级无损；原格式与时间精度需保护 |
| 整份 `hugo.toml` 写回 | 123 行整行注释变为 0，空的签名 `src` 字段被移除 | 首版禁止用通用表单编辑整份配置 |
| 混合 front matter | 用 TOML schema 读取 YAML 文件时，未识别标题，整份文件变成正文 | 增加格式检测/拒绝错误格式，不能共用单一固定格式强写 |
| 日期表单 | 默认日期字段无法读完整 ISO 时间；配置格式后，`08:30:45+08:00` 写回变为 `08:30:00+08:00` | 先保留带时区的 ISO 文本；日期选择器需额外适配精度 |
| 富文本核心转换 | `\(...\)`、`\[...\]` 分隔符消失，`details` 结构丢失；转换结果再经 Hugo 构建，公式从 4 处变为 2 处 | 暂不默认开放复杂文章富文本；保留源码通道 |
| 画板附件 | `.excalidraw` 被输出，页面引用对应 bundle 内资源 | 首版采用说明与附件上传；绘图界面以后单独接入 |
| 友链 RSS | 合法 YAML 中把链接的 `name` 放到 `url` 前，来源数从 1 变为 0 | 开放友链表单前先修复 YAML 解析 |

清空标签的样本中，旧标签确实被移除了，但 `tags: []` 的键也被删除。这不等于清空操作完全失败；风险在于空值与缺失值的语义可能不同，尤其涉及配置默认值或继承。

富文本测试使用上游锁文件同版本的 Tiptap 文档 schema 核心库，未挂载完整 React 表单，也未运行图片上传转换钩子。因此它证明了默认转换路径存在兼容风险，不代表完整浏览器操作已逐项验收。公式的 dollar 分隔符及本次 figure 短代码在探针中保留，不应扩大结论为所有公式、短代码都会损坏。

构建记录：[Hugo 对照结果](evidence/a0-hugo-results.json)。源码保存前后开发构建均为 35 页；生产构建为 30 页。原相册仅存在于 Git 快照中，没有被编辑。

## 认证与私有仓库

通过现有 Git 凭据执行只读 `ls-remote`，确认本站私有仓库和 `best` 分支可访问。没有创建 GitHub App、安装授权、远程分支或提交，也没有通过浏览器登录 CMS。**现有 Git 访问成功，不代表未来 CMS 的 GitHub App 已获得权限。**

源码显示：`lib/session-server.ts` 验证登录状态，`lib/token.ts` 根据用户令牌或协作者授权访问仓库；`lib/admin.ts` 使用 `ADMIN_EMAILS` 控制上游管理区。它们不构成本站所需的唯一站长账号限制。需要增加统一服务端准入，并对仓库/分支和 API 逐项验证；首版不开放邮箱协作者入口。

上游 App 建立脚本申请 `administration: write`、`actions: write`、`contents: write` 等权限。后续应核查是否能削减管理权限，并仅安装到本站仓库；不能称为只读 App。

文件保存代码把文件 SHA 传给 GitHub，已有文件冲突会返回 409，提供了冲突保护基础；本次没有实际调用远程写入验证这一路径。

| `app/(main)/[owner]/[repo]/[branch]/layout.tsx`、`components/repo/` | 仓库导航、本站入口与页面组织 |

| `app/api/[owner]/[repo]/[branch]/files/[path]/route.ts` | 保存、合并、冲突处理；实现最小扩展时重点验证 |

这里列的是可维护的源码修改位置，不声称上游已有任意看板插件接口。后台扩展会集中到本站模块，保留上游升级对照。

## 统计接口结论

本轮重新检索到官方文档及站点统计入口，确认其公开接入方式仍以页面脚本统计为主，官方提供 `count.php?search=域名` 形式的查询页面。本次没有找到经官方文档确认、适用于后台轮询的只读 JSON API；这不是证明服务绝对不存在该接口。

因此统计看板暂不直接调用上报接口、不抓取页面伪装成稳定 API、不伪造趋势图。可以先提供官方查询入口，正式数据仍等部署后验收；不更换用户已选定的第三方服务。[官方使用文档](https://www.busuanzi.cc/doc.php)、[官方统计入口说明](https://www.busuanzi.cc/)

## A1 之前必须落实的调整

1. 首版正文采用原生 `code` 字段的 Markdown 模式；元信息保留 `math` 开关，本站全局默认关闭数学渲染，公式文章需要显式开启。
2. 日期先保留完整 ISO 字符串，避免秒数/时区被普通日期控件改写；后续再提供无损的选择器。
3. 文章集合显式识别原 front matter 格式，不允许用错误 schema 写回；未知字段默认保留。
4. 定义文章空值语义并测试继承影响；整份 `hugo.toml` 保持只读，相册保持现状。
5. 建立单站长服务端准入与独立测试环境，然后验证 GitHub App 登录、错误账号拒绝、读取分支、保存和冲突。
6. 真正接入前核对并同步内容基线，避免 CMS 编辑远端旧内容；同步仍须在具体执行步说明，不由本次验证自动推送。
