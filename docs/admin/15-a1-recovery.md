# A1 异常提示与登录恢复验收

2026-10-02，用户明确选择先完成 A1 收尾。本步已完成本地实现与验收，未进入 A2、未推送或部署，也未写入或删除远端文章/素材。

## 使用变化

- 文章读取、保存失败显示持续提示，区分登录失效、授权不足、限流、网络/上游故障和版本冲突。网络故障不再统一误报“权限不足”。
- 登录失效时点击“在新标签页重新登录”，通过正常 GitHub OAuth 登录，然后返回原编辑页手动重试。原页标题、日期、简介、正文与保存版本保持；不自动保存、不使用安装令牌绕过站长授权。
- 限流尊重 Retry-After：提示剩余等待时间，阻止保存、手动重读和新的自动读取；并发成功响应不能缩短等待，历史 SHA 变化产生的读取也受限制。
- 远端版本冲突保留输入并要求比较版本，不盲目覆盖。未保存时刷新/离页会触发浏览器原生提醒；取消离开可以继续编辑。
- 本步没有持久化本地草稿。关闭或强制刷新页面仍可能丢失输入；站内切换页面的统一离开拦截也不属于本步。媒体库等其他页面没有全部升级为同一种恢复面板。

## 实现与检查

后台 `lib/repository-access.ts` 将仓库探测错误分为 401、403/404、429、502/503/504，处理 Octokit 将原错误包在 status 500 cause 内的情况，输出安全中文消息。既有站长、仓库、分支约束保留。

`lib/api-client.ts` 保留状态、Retry-After 并提供独立冷却状态；`entry.tsx` 和 `entry-recovery.tsx` 在既有 EntrySyncGuard 上增加提示、读取/保存重试和未保存提醒。错误不卸载已有表单、不采纳新的 SHA 覆盖未保存编辑。登录页只允许 reauth 参数再次启动正常 OAuth。
